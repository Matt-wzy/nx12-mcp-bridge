# DFM 事实清单与判决纪律（dfm-facts）

本文件定义“可制造性检查（DFM）”的测量与判决规则，借鉴 text-to-cad 制造性检查的
测量/判决分离哲学，与本项目 fail-closed 门禁同源。两条铁律：

> **铁律 1：测量工具只报事实，永不判 verdict。** `OK` 只表示“该测的都测到了”，
> 不是“可加工”的结论。
> **铁律 2：判决必须可溯源。** 每个数值比较都要带单位、容差与来源；
> 没有来源的规则不得使用。

## 1. 四态判决

| 状态 | 含义 | 用户输出要求 |
|---|---|---|
| pass | 实测值落在**已引用的适用限制**内 | 必须列出限制来源（标准章节 / 供应商规格 / 用户明示值） |
| fail | 实测值违反已引用的限制 | 必须给出实测值、限制值、来源与修改建议；不得擅自改设计 |
| review | 定性风险，暂无可量化限制可比对 | 披露事实，标注“建议人工/工艺确认” |
| unverified | 该项**未能测量**或无适用来源 | 必须如实列出；**禁止把 unverified 当成“无发现”或“合格”** |

## 2. 来源优先级（从高到低）

1. 用户本次明示的规格（对话文字 / 工艺要求）；
2. 用户自己的供应商规格（材料单、机床、工艺卡上写明的）；
3. 通用标准（GB / ISO，必须带标准号与章节号，如 GB/T 1182-2018 对应章节）；
4. 项目内置默认表——**当前为空**。不存在任何内置阈值表；缺来源时一律
   unverified，禁止编造默认值。

截图 / 渲染图 / PDF 只能支持怀疑，不能支持判定；“图上看着没问题”不是证据
（与 pipeline-contract §6.3 禁止从图片读数同源）。

## 3. 第一批可测事实（全部使用现有工具，零新增代码）

| 家族 | 测量来源 | 事实内容 | 典型用途 |
|---|---|---|---|
| 孔普查 | `nx_list_holes` | 直径/深度/位置/数量清单（只取 `kind=="hole"`） | 最小孔径、深径比 L/D、与工艺卡孔数一致性 |
| 质量与体积 | `nx_mass_properties` | 体积/表面积/质量/重心（密度可传） | 材料定额、毛坯利用率（配合 `nx_create_stock`） |
| 距离与角度 | `nx_measure_distance` / `nx_measure_angle` | 任意两棱边最小距离 / 夹角 | 配合间隙、壁间距、拔模候选的间接证据 |
| 包围盒跨度 | `nx_list_edges` 线性边极值 | X/Y/Z 跨度（同 Runner verify bbox 家族） | 毛坯尺寸、装夹行程 |
| 装配干涉 | `nx_check_interference` | 干涉体积 / 接触对 | 装配工艺可行性 |
| 螺纹代理披露 | Gate B / verify `approximations` | 底孔直径 = nominal − pitch | 必须披露“非真实牙型”，不得当真实螺纹交付 |
| 工艺卡字段 | `nx_export_process_card` | OP\<nn\>_ 属性模板缺字段 / typo 警告 | 工艺文件完整性 |

测量纪律：

- 距离/角度测量基于边索引，边索引是临时数据——测量前必须重新 `nx_list_edges`
  并按冻结筛选语法取边，禁止沿用旧索引（见 topology-safety.md）；
- 所有数值带单位（mm / deg），容差显式声明（默认 ±0.05，与 Runner verify 一致）；
- 每个家族输出必须有对应“事实块”（机器可读 JSON 或表格），不允许只写结论；
- `nx_list_faces` 的 `centroid_radius` 是**到全局原点的距离，不是圆柱面半径**
  （Loader 冻结语义）；任意圆柱面（圆角/凸台外圆）的半径当前没有可靠读数通道，
  相关检查只能 review / unverified。

## 4. 当前测不了的事实（固定输出 unverified + 原因，禁止伪装）

| 家族 | 需要的测量 | 现状 |
|---|---|---|
| 最小壁厚 | 面对面厚度场 | 无工具；只能用 `nx_measure_distance` 点抽测（review） |
| 拔模角 | 圆锥面半角 / 面法向分布 | 无完整读数（review） |
| 内圆角 vs 刀具半径 | 圆柱面真实半径 + 刀具库 | 半径读数通道缺失 + 无刀具库来源（unverified） |
| 真实螺纹牙型 | UF SymbThread（marshal 破损） | 判死刑探针已归档（受阻项调研档案） |
| 悬垂 / 支撑（3D 打印） | 面法向射线分析 | 无工具 |

对这些家族：一律输出 unverified 并写明原因，禁止用 review 伪装成 pass，
更禁止跳过不报。

## 5. 改版纪律（Check a redesign）

几何一经修改（verify 失败后的修复、人工改模、参数调整），此前所有 DFM 结论
**全部失效**；必须对最新 PRT/STEP 重新测量。禁止引用旧 revision 的测量结果
作为新版本的判据。“移动一个孔，可能在旁边打开一个新的发现。”

## 6. 与 Runner verify 的分工

- `runner.py verify`：**计划 vs 实际**——模型是否按 plan/drawing 长出来
  （机器审计，exit code 门禁，见 pipeline-contract §5.3）；
- 本文件：**实际 vs 工艺约束**——零件能不能被加工（测量事实 + 受引导判决，
  判决由 Agent 按 §1/§2 在对话层给出）；
- verify 的 fail 是交付阻塞；DFM 的 fail 是工艺风险披露，不阻塞 Runner 门禁，
  但必须进入用户输出，不得静默丢弃。
